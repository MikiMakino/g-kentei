# AIの社会実装

G検定では、AIモデルそのものだけでなく、**AIを事業で安全に活用するための進め方**も問われる。

## AIプロジェクトの進め方

| 段階 | 内容 | 注意点 |
|------|------|--------|
| 課題設定 | ビジネス課題をAIで解くべきか判断 | AI導入が目的化しないようにする |
| データ確認 | 必要なデータの有無・品質・利用権限を確認 | 個人情報、著作権、偏りに注意 |
| PoC | 小さく試作して実現可能性を検証 | 精度だけでなく費用対効果も見る |
| 開発 | モデル・システム・運用設計を行う | 説明可能性、監査ログ、セキュリティ |
| 運用 | 性能監視・再学習・改善を継続 | データ分布の変化に対応 |

!!! warning "PoCで終わらせない"
    PoC（概念実証）は技術的に可能かを確かめる段階。業務導入には、運用体制、責任分界、コスト、ユーザー教育まで設計する必要がある。

## データの収集・加工・分析・学習

AIの性能はデータ品質に大きく依存する。

- **データ収集**：目的に合うデータを集める。利用許諾・個人情報・著作権を確認する。
- **アノテーション**：画像や文章に正解ラベルを付ける。基準の統一が重要。
- **前処理**：欠損値処理、外れ値処理、正規化、重複除去を行う。
- **データ拡張**：画像の回転・反転などで訓練データを増やす。
- **評価**：訓練データではなく、検証データ・テストデータで汎化性能を見る。

## MLOps

**MLOps** は、機械学習モデルを継続的に開発・運用するための考え方。

| 要素 | 説明 |
|------|------|
| バージョン管理 | データ、特徴量、モデル、コードを記録 |
| 継続的学習 | 新しいデータで再学習し性能を維持 |
| 監視 | 精度低下、データ分布の変化、異常入力を検知 |
| 再現性 | いつ・どのデータ・どの設定で学習したか追跡 |

### データドリフト

運用中に入力データの分布が学習時と変わること。

例：季節変動、ユーザー層の変化、法制度変更、流行語の変化。

## AI活用の判断軸

| 観点 | 確認すること |
|------|--------------|
| 実現可能性 | 十分なデータがあるか、精度要件を満たせるか |
| 価値 | 業務効率化、売上向上、品質改善につながるか |
| リスク | 誤判定時の被害、差別、プライバシー侵害 |
| 説明可能性 | 利用者・監査者に判断根拠を説明できるか |
| 人間の関与 | 最終判断を人間が行うべき領域か |

## 産業応用の例

| 分野 | AI活用例 |
|------|----------|
| 製造 | 外観検査、予知保全、需要予測 |
| 医療 | 画像診断支援、創薬、問診支援 |
| 金融 | 不正検知、与信審査、顧客対応 |
| 小売 | レコメンド、在庫最適化、価格最適化 |
| 物流 | 配送計画、需要予測、倉庫自動化 |

!!! note "試験ポイント"
    AIは万能ではない。データ品質、業務設計、人間の監督、法令・倫理への配慮を含めて社会実装する。
